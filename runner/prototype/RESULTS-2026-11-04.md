# Does the save-to-action loop work? Run on 69 real saves, Nov 4

For Sam, deciding whether to build this into the system. Inputs: the Oct 26 archive (69 saves, Oct 7 to 26, both accounts) plus gold OP replies. Models: gpt-6-luna for triage, gpt-6.1-sol for everything else, all through CLIProxyAPI. No Claude model ran in the pipeline. I (Opus) ran the scripts and did the prep steps.

So 17 of 69 saves (25%) got a non-trivial per-post proposal, and about 2 to 4 of those are things you would tap yes on tonight. The per-post loop alone is not the product. Clustering is what turned seven redundant ledger proposals into one action.

## The three preps

1. **Watcher completeness gate** (from @hqmank's eval post; the insight is his own follow-up, R4: "test what was already working"). `prepared/watcher-replay-gate/` gives every expected item an outcome and every check a verdict. Its 8 tests replay the real Nov 3 Pomerado recordings: anthropic news 5 of 5 complete, Luma Austin 5 of 5 flagged (recall 0.22), Luma SF flagged (0.63), a repeat check passes as a quiet run. Two deliberate breaks each fail tests. Limit: it needs an independent parser per source, and it found no omission the Nov 3 audit hadn't. Approval: "Add the completeness gate to watcher-proto so a watcher that drops items can't graduate? 8 replay tests pass."
2. **Mac agent preflight** (from @dominikmartn's Black October post). The post's gist had moved to a repo with newer checks. `prepared/mac-preflight/` holds a read-only script adapted from it, plus a run on this Mac. It found your own Caret 2.app shipping Node 26.5.0 with the unpatched Brotli decoder (pinned at `apps/caret/scripts/build-app.sh:40`; patch drafted with the 26.12.1 checksum), API for Cursor.app on Node 22.23.1, mise Node 24.21.0, python.org 3.13 with pip 25.0.1, Chrome .75, and macOS 26.6.2. Claude Code, Bun, Homebrew Node and uv were patched. The extension-trojan indicators came back clean. Approval: "Run fixes: Caret Node pin PR, mise Node 24.22.1, pip 26.2.2 for python.org 3.13, and the TLS probe? macOS and Chrome need you."
3. **Cache and compaction** (from @lydiahallie). This prep overturned its proposal. Sol proposed a cache TTL change; the transcripts show 100% of 285M cache-write tokens in the last 7 days already at 1h, because `ENABLE_PROMPT_CACHING_1H=1` was kept on purpose after your Aug 6 audit (`AgentSetup/docs/validation.md:103`). The other half of her post still applies: 43 Opus sessions passed 400K this week, and context above 600K was 10.1% of Opus volume. Approval: "Set autoCompactWindow to 600k for Claude Code? Over the last 7 days, Opus sent up to 10% less context. 1h cache stays."

Sol ranked the fx0 crash-recovery suite second. I swapped in the cache item because fx0 overlapped #1 and targets an approval dispatch path watcher-proto hasn't built yet (`raw/prepared.json`).

## Cluster actions (`clusters.json`)

1. Make recovery and approval one executable ledger contract (5 posts: @DavidKPiano R1, fx0 source, two @poteto statechart posts, Nessa).
2. Gate watcher expansion on completeness (3 posts: Pomerado launch, the Duet 8-layer PDF, @hqmank R4). Prep 1 is its first piece.
3. One enforced Mac-runner launch boundary: credential broker plus preflight (@avrldotdev thread and R5, Black October repo). Prep 2 is half of it.
4. Require landed-task evidence before routing changes (4 posts: two Theo dashboards, Theo's multi-account post, Lydia's R1).
5. Pair Reel Studio's visual review with a replayable upload-to-preview test (tester-army/e2e, Lavish).

Four of the five are test or gate work on the ledger and agent setup. That matches what you saved this month, but none of them touches Curate's product, classes or Base Power. Eleven design references went to a kgu.one shelf with no action, which is defensible but means the design saves produced nothing.

## What deep reading added

On 5 posts, Sol saw only the post text and proposed an action. A blind Sol judge with the full thread compared the two. Deep won 4. Twice the win was a correct decline where the shallow read invented work: benchmarking Flint, whose sources already list hardware limits, and "recover the context" for an Armor post whose quote already held it. Twice the thread supplied the concrete method: Jem's follow-ups explain the shared 58u grid, and replies point to broll-mcp, which already does what the shallow read wanted built. Deep lost once (Strawberry), declining where a bounded trial was reasonable. Caveats: n=5, the judge is the same model, and 3 of the 5 were picked for having the most context.

## What failed

- **"Already in place" from a prose summary is unreliable.** Luna dropped Lydia's post for a wrong reason, Sol rescued it, and Sol proposed a change you made in August. Only the prep's look at real settings caught it. A live state probe has to run before proposals.
- **Proposals target code that doesn't exist.** Eight proposals and two cluster actions name paths like `ledger/tests/watchers/replay/`. The ledger is a plan plus `watcher-proto`, whose approval endpoint is unbuilt.
- **A dot it missed.** @treg_ai's save pitches Treg, and the Black October repo says Treg was breached Oct 22. That line sat past the 7,000-character README cut, so no model saw both. Treg was declined for another reason.
- **The judge is lenient.** Sol judging Sol found 0 busywork; I count 3 or 4 (Lavish trial, brag-slim comparison, assay judge audit, Nessa).
- **Missing context.** 26 videos went untranscribed, including a 71-minute one. Images were OCR only in 18 posts. 9 sources were unreadable (JS pages, 403s, Spotify, Drive). Gold marks 49 of 69 self-threads incomplete. 12 posts had no replies.
- **Most approvals are "open a PR."** That fits the policy, but approval time (median 30 s) is Sol's guess, not a measurement.
- **No prompt caching.** The gateway reported 0 cached tokens even though every call repeats the same context, so $1.53 is the uncached ceiling.

## Verdict

Worth building, with three changes: run the state probe before proposing, cluster before showing anything, and treat prep as verification (prep 3 changed its answer and prep 2 found a real at-risk binary in your own app). Show cluster actions and prepared items. Keep per-post proposals as evidence behind them.
