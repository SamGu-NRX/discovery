The 7 saves both methods read

Each bar shows how many of the posts the archive's judge kept that collector had found. Together the two found all 138.

  • Computer use missed 23, mostly quote posts. X's quotes page showed "this page doesn't exist" for every save the pilot opened. Fetch mode finds them through search.
  • Fetch mode missed 25. Emil's post is a reply, and the pilot read all 86 replies of the post it answers. Fetch mode reads that parent but not its replies, which cost 16. On Mollick, fetch mode lost 4 to the request and branch limits in place then, and 3 to second pages of searches, which X won't serve to replayed requests.

At scale, fetch mode only

  • 60 saves in 1,889 requests and 123 minutes, 60 of them spent waiting to keep 30% of X's request budget free.
  • Both reply orders reached their end on all 60 saves. 13 saves had more reply branches than the 15-per-post limit, 284 in all. Follow-up gap runs fetch those, at about 2 requests a branch.
  • On 48 of 60 saves it collected at least X's reply count. 12 are short even though both orders reached the end, mostly four posts with 588 to 1,085 replies. X's count includes replies its views don't show this account. No page check was made.

For the daily pipeline

  1. Collect with fetch mode, sending to the Worker. About 3 new saves a day need 1–2 bookmark requests and 50–170 post requests, inside one 15-minute window and 2–8 minutes of wall time.
  2. Close two gaps first. Read the conversation of the post a save replies to, and keep the per-post cap at 80 or more.
  3. Add a daily trigger. Today someone has to press Start. The lens branch's hourly re-poll already opens the fetch page from an alarm; a daily job can use the same path. Not built yet.
  4. Keep computer use as the fallback for when X changes something fetch mode depends on, and for second pages of searches.
  5. Decide on GrokBot after its trial. It is the only option that works while Sam's Chrome is closed, and it reads bookmarks through X's paid API. Fetch mode reads X's internal API from Sam's session, which X's terms don't allow; nothing shows how X treats that at this volume.

To measure GrokBot

  1. Follow round 2's SETUP.md steps 2 and 3 on the MacBook: connect X with write permissions off, paste the daily routine, and record the day-0 boundary.
  2. Once, in a new GrokBot chat, send the request below. It reads the same 7 saves in the inbox format the routine uses.
  3. Export the inbox and score it with extension/tools/x-direct-score-judged.mjs --grokbot <export.json>. Also note the quota share and the X credits spent.
